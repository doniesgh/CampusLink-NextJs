1. Vue d'ensemble du projet

CampusLink centralise les services numériques de la vie étudiante dans une seule application, installable sur téléphone et ordinateur sans passer par un store, et consultable hors ligne pour l'essentiel (emploi du temps, annonces). Une application mobile Flutter est prévue : elle utilisera la même API.

Architecture en bref

PartieRôleDossier
Application webNext.js 16 (App Router), React 19, Tailwind CSS 4, next-intl (français / anglais). Pages serveur, Server Actions, relais /bff vers l'API, service worker (hors ligne, push).next/
APIExpress 5 + Mongoose 9 : routes REST /api/*, temps réel Socket.IO (chat), tâches planifiées, e-mails, push, PDF.backend/
Base de donnéesMongoDB 7 (local, Docker ou MongoDB Atlas).—
TestsPlaywright : tests d'API, tests de sécurité, tests navigateur.tests/
DocumentationArchitecture, déploiement, spécifications, contrats d'API, qualité, démos.docs/
Principe clé. Le navigateur ne parle jamais directement à l'API REST : les jetons de session sont dans des cookies httpOnly gérés par Next.js, qui appelle l'API avec un jeton Bearer. Seul le chat temps réel se connecte directement à l'API, avec un ticket de 60 secondes. L'API ne dépend d'aucun cookie, ce qui la rend directement utilisable par l'application Flutter.

Rôles

RôleCe qu'il peut faire
ÉtudiantEmploi du temps de son groupe, annonces, notifications, réservations, forum, « Mon suivi » (présences, notes, bilan PDF), covoiturage, marketplace, demandes de mentorat.
EnseignantSon emploi du temps, annonces vers ses groupes, appel, notes, réservations, forum (réponses certifiées), marketplace, réseau alumni.
AdministrationTout gérer : utilisateurs, structure académique, emploi du temps, annonces, ressources et réservations, modération (forum, marketplace, alumni), suivi des étudiants, journal d'audit.
AlumniAnnonces, forum, profil alumni (avec consentement), mentorat, fil d'actualités alumni.

L'inscription publique crée toujours un compte étudiant. Les autres rôles sont attribués par l'administration.

4. Guide utilisateur

4.1 Premiers pas (tous les rôles)

Se connecter

Ouvrir le site, puis Se connecter avec son e-mail et son mot de passe. Cocher « Rester connecté » pour une session de 30 jours. Si la validation en deux étapes est activée, saisir le code à 6 chiffres reçu par e-mail.

Mot de passe oublié : lien sur la page de connexion, puis lien reçu par e-mail (valable 30 min).

Langue

Sélecteur Langue en bas du menu (ou sur la page de connexion) : Français / English. Le choix est enregistré sur le compte et utilisé pour les e-mails, les notifications et le bilan PDF.

Mon compte

Menu Compte : prénom et nom, langue, validation en deux étapes, changement de mot de passe, notifications push sur cet appareil (« Activer les notifications push »).

Installer l'application

Sur un site en HTTPS, le navigateur propose « Installer » (Chrome / Edge : icône dans la barre d'adresse ; Android : « Ajouter à l'écran d'accueil » ; iPhone : Partager → « Sur l'écran d'accueil »).

Hors ligne

Les pages déjà consultées (accueil, emploi du temps, annonces, notifications, forum, réservations, suivi) restent lisibles sans réseau. Un bandeau « Tu es hors ligne » s'affiche ; les actions faites hors ligne (annonce lue, réponse au forum) sont envoyées au retour du réseau.

Notifications

La cloche du menu indique les notifications non lues : changements d'emploi du temps, annonces, réservations, forum, présences, notes, covoiturage, marketplace, mentorat. Tout marquer comme lu depuis la page Notifications.

5.2 À faire après le premier git pull de cette version

Important. backend/.env n'est plus suivi par git (il contenait des secrets). Sauvegardez votre backend/.env avant de faire git pull : git le supprime de votre dossier. Recréez-le ensuite à partir de backend/.env.example. L'ancienne variable SECRET n'est plus lue : JWT_SECRET est obligatoire.
  1. Sauvegarder backend/.env, puis git pull sur main.
  2. npm install dans backend/, next/ et tests/ (nouvelles dépendances).
  3. Recréer backend/.env depuis backend/.env.example (étape 5.3).
  4. Remplir la base : npm run seed:demo, puis créer son compte administrateur.

5.3 Installation pas à pas

1. Récupérer le code et lancer MongoDB

git clone https://github.com/doniesgh/CampusLink-NextJs.git
cd CampusLink-NextJs
# MongoDB dans Docker (si vous n'avez pas de service MongoDB local)
docker run -d --name campuslink-mongo -p 27017:27017 -v campuslink-data:/data/db mongo:7

2. API (backend)

cd backend
npm install
cp .env.example .env                  # Windows PowerShell : Copy-Item .env.example .env
# Générer un secret et le coller dans JWT_SECRET= (fichier .env)
node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
npm run generate-vapid                # copier les deux clés dans VAPID_PUBLIC_KEY / VAPID_PRIVATE_KEY
npm run seed:demo                     # données de démonstration (facultatif)
npm run create-admin -- votre.email@esprit.tn MotDePasseSolide Prénom Nom
npm run dev                           # API sur http://localhost:4000 (redémarre à chaque modification)

3. Application web (autre terminal)

cd next
npm install
cp .env.example .env.local            # API_URL=http://localhost:4000 par défaut
npm run dev                           # site sur http://localhost:3000
E-mails en local. Sans SMTP_USER / SMTP_PASS, les e-mails (code de connexion, lien de réinitialisation) ne sont pas envoyés : ils s'affichent dans la console de l'API. Pour un vrai envoi, utiliser un mot de passe d'application Gmail.

Règles à respecter

  • Contrats : chaque phase a un contrat (docs/phase1|2|3-contract.md) qui fixe les routes, les règles, les codes d'erreur et les écrans. Modifier le contrat avant de changer un comportement.
  • Erreurs de l'API : toujours { error, code, details? } avec un code stable (le web et Flutter s'appuient dessus).
  • Textes : jamais de texte en dur dans l'interface ; ajouter la clé dans messages/fr/…json et messages/en/…json (vérifié par TypeScript). Français au tutoiement.
  • Appels API côté web : par le serveur (serverApi, Server Actions) ou par le relais /bff ; jamais d'appel direct du navigateur vers l'API REST.
  • Couleurs : utiliser les jetons du thème (bg-primary, text-muted-foreground…), jamais de couleur en dur (mode sombre).
  • Avant de pousser : npx tsc --noEmit et npm run lint dans next/, npm run test:api dans tests/.
  • Git : une branche par fonctionnalité, des commits courts et thématiques, une pull request vers main. Ne jamais committer .env.

8. Déploiement gratuit (Vercel + Render + MongoDB Atlas)

Configuration choisie pour une mise en ligne gratuite : le site sur Vercel, l'API sur Render, la base sur MongoDB Atlas. HTTPS est fourni par les deux hébergeurs (nécessaire pour la PWA et le push).

Étapes

  1. MongoDB Atlas (atlas.mongodb.com) : créer un cluster gratuit M0, un utilisateur de base de données, autoriser l'accès réseau 0.0.0.0/0 (Render n'a pas d'IP fixe), copier la chaîne de connexion mongodb+srv://….
  2. Render (render.com) : New → Blueprint, choisir le dépôt GitHub ; le fichier render.yaml du dépôt crée l'API (dossier backend, node app.js, contrôle de santé /api/health, fichiers stockés dans MongoDB). Renseigner MONGO_URI, les clés VAPID, l'adresse du site, et le SMTP si besoin.
  3. Vercel (vercel.com) : Add New → Project, importer le dépôt, Root Directory = next, variables API_URL et NEXT_PUBLIC_REALTIME_URL = adresse Render, NEXT_PUBLIC_APP_TIMEZONE = Africa/Tunis, TRUSTED_PROXY_HOPS = 1. Le fichier next/vercel.json impose le framework Next.js et npm ci (sinon Vercel sert le dossier comme un site statique, ou choisit pnpm à cause de l'ancien pnpm-lock.yaml).
  4. Reporter l'adresse Vercel dans CORS_ORIGINS et APP_URL sur Render.
  5. Remplir la base en ligne depuis un poste de l'équipe : MONGO_URI=<Atlas> STORAGE_DRIVER=gridfs npm run seed:demo, puis npm run create-admin.
  6. Garder l'API éveillée : un moniteur gratuit (ex. UptimeRobot) qui appelle /api/health toutes les 10 minutes.
Limites de l'offre gratuite. Sans requête pendant 15 minutes, l'API Render se met en veille (premier appel lent, ≈ 50 s) — d'où le moniteur. Atlas gratuit : 512 Mo (données + fichiers). Le chat et les tâches planifiées tournent sur une seule instance.

9. Sécurité : ce que chacun doit savoir

  • Secrets : .env et .env.local ne sont jamais commités. Les anciens SECRET et FCM_SERVER_KEY sont visibles dans l'historique git (commit 12a8462) : ils doivent être considérés comme compromis et changés.
  • Production : générer de nouveaux JWT_SECRET et clés VAPID ; ne jamais utiliser les comptes de démonstration (Campus123!).
  • Mots de passe et codes : hachés (bcrypt / SHA-256) ; codes à usage unique et liens de réinitialisation limités dans le temps.
  • Limitation des tentatives : active par défaut (connexion, codes, mots de passe, écritures des modules) ; RATE_LIMIT_ENABLED=false seulement en développement.
  • Données personnelles : profils alumni privés sans consentement, e-mails partagés seulement après un mentorat accepté, coordonnées de covoiturage arrondies pour les non-participants, comparaison de notes à partir de 5 étudiants, données hors ligne effacées à la déconnexion.
  • Journal d'audit : les actions sensibles sont tracées (consultable par l'administration).
  • Avant chaque fusion : faire passer tests/api/security.spec.ts.

10. Problèmes fréquents et solutions

SymptômeSolution
L'API s'arrête : « Could not connect to MongoDB »MongoDB ne tourne pas. Service Windows : Start-Service MongoDB (PowerShell administrateur) ; Docker : docker start campuslink-mongo. Vérifier MONGO_URI.
L'API refuse de démarrer : « Missing required environment variable »Créer backend/.env depuis .env.example et remplir MONGO_URI et JWT_SECRET.
« Port 4000 / 3000 already in use »Un serveur tourne déjà : le fermer, ou changer PORT (API) / -p (Next).
« Another next dev server is already running »Next.js 16 : un seul next dev par dossier. Fermer l'autre terminal.
tsc échoue dans .next/dev/typesFichiers générés périmés : supprimer next/.next/dev puis relancer.
« Impossible de joindre le serveur » sur le siteL'API n'est pas lancée ou API_URL est faux (next/.env.local).
Je ne reçois pas le code de connexion / le lien de réinitialisationSans SMTP, ils sont affichés dans la console de l'API.
Erreur 429 « Trop de tentatives » en développementAttendre la fin de la fenêtre, ou RATE_LIMIT_ENABLED=false dans backend/.env.
Le hors ligne ou le push ne marchent pasLe service worker n'existe qu'en build de production (section 5.6) ; le push demande aussi les clés VAPID et l'autorisation du navigateur.
Le chat du covoiturage ne se connecte pasNEXT_PUBLIC_REALTIME_URL doit pointer vers l'API au moment du build ; l'adresse du site doit être dans CORS_ORIGINS.
Erreur d'hydratation liée à data-dav10 dans la consoleExtension de navigateur (Office/WebDAV) : sans gravité, déjà neutralisée sur <html>.
Données de démonstration « dans le passé »Relancer npm run seed:demo (idempotent) : les données sont recalées sur la date du jour.
